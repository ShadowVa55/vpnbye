# 4. Если не работает

## WireGuard / AmneziaWG

**Подключается, но интернета нет**

> Сначала проверьте: сервер ставился с `--lan-only`? Тогда так и должно быть —
> в туннель идут только `10.66.66.0/24` и ваша LAN, интернет работает напрямую.
> Это режим для сервера в России / доступа к домашней сети.

1. На сервере: `sysctl net.ipv4.ip_forward` → должно быть `1`.
2. Проверьте NAT: `iptables -t nat -L POSTROUTING -n -v` — должна быть строка с
   `MASQUERADE` и вашей подсетью.
3. Внешний интерфейс в правилах должен совпадать с реальным:
   `ip route show default` (обычно `eth0`, но на Hetzner бывает `enp7s0`).
   Если не совпадает — поправьте `PostUp`/`PostDown` в конфиге и перезапустите
   `systemctl restart wg-quick@wg0`.
4. Firewall провайдера: UDP-порт должен быть открыт и в `ufw`, и в панели хостера.

**«Последнее рукопожатие» не появляется (0 B получено)**

* Проверьте, что клиент ходит на правильный `Endpoint` (публичный IP, а не приватный).
* `wg show` на сервере: если пир есть, но handshake нет — пакеты не доходят.
  Снаружи проверьте: `nc -uzv IP 51820` или `nc -zvu IP 51820` (иногда нужен
  `sudo`, т.к. для UDP результат приблизительный).
* Если провайдер режет UDP — попробуйте другой порт (443/udp часто пропускают)
  и перезапустите скрипт с `--port 443`.

**Подключается, работает пару минут, потом «умирает»**

Классика для мобильных сетей и ТСПУ: DPI вычислил WireGuard.
→ Переходите на AmneziaWG (`amneziawg/install-amneziawg.sh`).

**Медленно, сайты открываются через раз**

Проблема MTU/фрагментации: уменьшите `MTU` в конфиге клиента (1420 → 1380 → 1280)
и перезапустите туннель.

## VLESS + REALITY

**`systemctl status xray` — failed**

```bash
xray -test -config /usr/local/etc/xray/config.json   # покажет, что не так
journalctl -u xray -n 50 --no-pager
```

Частые причины: порт 443 занят (nginx/web server), `dest` недоступен с сервера,
в конфиге остались плейсхолдеры.

**Подключается, но трафик не идёт**

* `sni` в клиенте должен совпадать с `serverNames` в конфиге.
* IP-адрес, а не домен, в ссылке — это нормально, но при смене IP ссылку надо обновить.
* Проверьте, что сервер может достучаться до сайта-прикрытия:
  `curl -I https://www.microsoft.com --max-time 5`.
* Клиент должен поддерживать **XTLS-Vision** (v2rayNG ≥ 1.8, Hiddify, NekoBox, Streisand).

**Соединение рвётся через несколько минут**

Смените сайт-прикрытие (`--sni`) на другой зарубежный сайт с TLS 1.3 и H2,
например `www.samsung.com`, `dl.google.com`, `www.lovelive-anime.jp`.

## Универсальные команды диагностики

```bash
# на сервере
wg show                                  # пиры, handshake, трафик (WireGuard)
awg show                                 # то же для AmneziaWG
journalctl -u wg-quick@wg0 -n 50 --no-pager
journalctl -u awg-quick@awg0 -n 50 --no-pager
journalctl -u xray -n 50 --no-pager
ss -lunp | grep -E '51820|443'           # слушает ли порт
ufw status verbose
ip a show wg0                            # есть ли интерфейс и адрес
iptables -t nat -L POSTROUTING -n -v     # работает ли NAT
```

```bash
# на клиенте (Linux/macOS)
ping -c 3 10.66.66.1                     # доступен ли сервер внутри туннеля
curl -s https://ifconfig.me              # какой IP видит интернет
```

## Когда сервер «сгорел»

Если IP попал в блок-лист и перестал работать на всех протоколах:

1. Пересоздайте сервер / закажите новый IP у хостера (обычно 1–3 €).
2. Перезапустите нужный скрипт установки — конфиги сгенерируются заново.
3. Клиентам — новые файлы/ссылки (старые ключи к новому серверу не подойдут,
   если вы не переносили `/etc/wireguard`).

Держите резервную копию каталога конфигов, тогда переезд на новый IP — это правка
одной строки `Endpoint` в клиентских файлах.
