# 6. Клиенты в России: рабочая схема

Схема: **клиент в РФ → сервер за границей**. Российский сервер обход блокировок
не даёт (см. [05-server-in-russia.md](05-server-in-russia.md)), поэтому сервер —
NL/DE/FI/SE, а вся борьба идёт на уровне протокола и порта.

## Что выбрать: AmneziaWG или REALITY

| | AmneziaWG | VLESS + REALITY |
|---|---|---|
| Что видит провайдер | непонятный UDP-поток | HTTPS-сессию к `www.microsoft.com` |
| Скорость | выше (UDP, минимум оверхеда) | ниже на 10–25 %, но стабильно |
| Батарея на телефоне | лучше | хуже (TLS + TCP) |
| Устойчивость к ТСПУ | высокая | максимальная |
| Сложность клиента | приложение AmneziaVPN | v2rayNG / Hiddify / Streisand / FoXray |
| Когда НЕ работает | там, где режут весь UDP (некоторые тарифы, роуминг) | почти всегда работает |

Практика: **начните с AmneziaWG на 443/udp**. Если провайдер/оператор его душит
(подключается, но скорость ~0 или рвётся) — переходите на REALITY. Держите оба:
клиенты спокойно хранят несколько профилей, и в поездке вы переключаетесь в один тап.

```bash
# 1) основной вариант
sudo bash amneziawg/install-amneziawg.sh --clients 2 --port 443

# 2) резервный вариант на том же сервере (другой порт не нужен: TCP/443 vs UDP/443)
sudo bash xray/install-xray-reality.sh --names phone,laptop --sni www.microsoft.com

# 3) проверка, что всё живо
sudo bash scripts/preflight.sh
```

TCP/443 и UDP/443 не конфликтуют — можно держать оба протокола на одном сервере.

## Порт: как выбрать

* `443/udp` — лучший выбор для AmneziaWG: выглядит как QUIC/HTTP3, почти всегда открыт.
* `51820` — заводской порт WireGuard, его чаще всего и режут первым. Не оставляйте.
* `2408`, `8443`, `1194`, `500`, `4500` — «бытовые» значения, если 443 занят или душат.
* Смена порта — самый быстрый способ проверить, что дело именно в фильтрации порта.

Сменить порт у уже установленного AmneziaWG:

```bash
sudo sed -i 's/^ListenPort = .*/ListenPort = 2408/; s/--dport 51820/--dport 2408/g' \
  /etc/amnezia/amneziawg/awg0.conf
sudo systemctl restart awg-quick@awg0
ufw allow 2408/udp 2>/dev/null || true
# и в клиентском конфиге поправить Endpoint = IP:2408
```

## Сайт-прикрытие для REALITY (`sni`)

Требования: зарубежный сайт, TLS 1.3 + HTTP/2, без редиректов, желательно
географически близкий к вашему серверу и **не заблокированный в РФ**.

Проверенные варианты: `www.microsoft.com`, `dl.google.com`, `www.samsung.com`,
`www.lovelive-anime.jp`, `swdist.apple.com`.

Проверка с сервера (установщик делает это сам):

```bash
curl -fsSI --max-time 8 https://www.microsoft.com -o /dev/null -w '%{http_code}\n'
echo | openssl s_client -connect www.microsoft.com:443 -tls1_3 -alpn h2 -servername www.microsoft.com 2>/dev/null | grep 'ALPN protocol'
```

Если во второй команде не `ALPN protocol: h2` — сайт не подходит.

## MTU: главная причина «сайты грузятся наполовину»

Мобильные операторы РФ часто дают MTU 1400 и меньше. Симптомы: сообщения в
мессенджерах идут, картинки/видео нет, HTTPS-страницы висят.

```bash
# на сервере: узнать реальный PMTU
ping -c1 -M do -s 1372 1.1.1.1        # 1372+28 = 1400
```

Затем в клиентском конфиге:

| PMTU на пути | MTU клиента |
|---|---|
| 1500 | 1420 (WireGuard) / 1420 (REALITY) |
| 1400 | 1360 |
| 1300 | 1280 (дефолт AmneziaWG) |

`--mtu 1280` при установке — безопасный универсальный вариант, если не хочется думать.

## Чек-лист первого запуска

1. Сервер за границей, IP свежий (`curl -4 ifconfig.me` совпадает с тем, что в конфиге).
2. `--port 443` для AmneziaWG, `--sni` проверен (TLS 1.3 + h2).
3. `sudo bash scripts/preflight.sh` — нет FAIL, часы в порядке.
4. На телефоне: сначала Wi-Fi (там обычно нет DPI), потом мобильный интернет.
5. Если на мобильном не идёт — смените порт, потом протокол (AmneziaWG ↔ REALITY).
6. Проверьте «IP на выходе»: `curl https://ifconfig.me` должен показать IP сервера.

## Если «подключается, но интернета нет» / рвётся

| Симптом | Что делать |
|---|---|
| Рукопожатие есть, трафик 0 | блокировка на уровне DPI → сменить порт, затем протокол |
| Работает 1–3 минуты, потом тишина | DPI распознал поток → на REALITY (TCP/443 выглядит как обычный HTTPS) |
| Работает только по Wi-Fi | оператор режет UDP → REALITY (TCP) или UDP/443 |
| Медленно, часть сайтов не грузится | MTU: уменьшить до 1280–1360 |
| Работало и внезапно перестало | IP попал в блок-лист → сменить IP у хостера, обновить `Endpoint` в конфигах |
| REALITY не подключается | проверить `vless://`-ссылку: `sni` = `serverNames`, `pbk` = публичный ключ, `sid` = shortId |

## Обновление конфигов при смене IP

Ключи остаются, меняется только адрес. Поправить всех клиентов можно так:

```bash
# на сервере: ключи остаются, меняется только адрес в клиентских файлах
NEW_IP=203.0.113.10
for f in /root/wg-clients/*.conf /root/awg-clients/*.conf; do
  [[ -f "$f" ]] || continue
  port="$(sed -n 's#^Endpoint = .*:\([0-9]\+\)$#\1#p' "$f" | head -1)"
  sed -i "s#^Endpoint = .*#Endpoint = ${NEW_IP}:${port:-51820}#" "$f"
  echo "обновлён $f"
done
```

Для REALITY проще пересоздать ссылки: IP подставляется при каждом запуске
`xray/add-client.sh` (он берёт актуальный внешний адрес), либо замените IP
в `vless://`-ссылке вручную — остальные параметры трогать не нужно.

## Правовая рамка (кратко)

Сервер — ваш, доступ — только для себя и близких. Продажа доступа к
заблокированным ресурсам в РФ квалифицируется как деятельность анонимайзера
(ФЗ-149, ст. 15.8) — этого делать не надо. Подробнее и про риски российского
хостинга: [05-server-in-russia.md](05-server-in-russia.md).
